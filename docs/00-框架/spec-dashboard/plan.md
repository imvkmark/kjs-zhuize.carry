# Carry 追责系统工作台 · 页面骨架结构（Markdown 版）

## 一、三层架构总览

```
dashboard/
├── data/                          # 数据层（人 + git 维护，JSON）
│   ├── review-v1.0.json           # 评审结论/门禁/P0/P1/Open
│   ├── feedback.json              # 评论反馈 (26)
│   ├── questions.json             # 问题清单 (35)
│   ├── external-deps.json         # 外部依赖 (15)
│   ├── blockers.json              # 阻塞项 (3)
│   ├── code-diff.json             # 代码差异 (17，可 git 自动生成)
│   ├── gap.json                   # GAP 清单 (51)
│   └── refs.json                  # 架构/流程/模块/文档中心 引用
│
├── index.html                     # 渲染层：唯一入口，不写死业务数据
├── v1.0-review-2026-07-30.html    # 评审详情子页（保留）
└── md-viewer.html                 # 保留
```

原则：**index.html 只是模板**，运行时 `fetch('data/*.json')` 填充；改数据不动模板。

## 三、卡片组件的通用数据结构（供 JS 渲染用，非最终 JSON schema）

```
Card {
  id: string            # 对应 data/*.json 的 key
  icon: string
  title: string
  count: number
  urgency: "realtime" | "weekly" | "quarterly"   # 决定角标/颜色
  visibleTo: [role]      # 决定角色过滤时是否显示
  actions: ["copy", "detail", "link"]
  source: string          # 数据来源说明（如"钉钉群/IM 手动汇总"），仅内部标注，非用户可见
}
```

## 四、角色 → 可见子项映射表

| 角色 | 优先展示子项 | 隐藏/折叠子项 |
|---|---|---|
| 老板 | 顶部状态条 + 时间线 | 全部 12 张卡片默认折叠，仅展开阻塞项 |
| 产品 | 问题清单、GAP、现状对齐、评审详情 | 技术架构类 |
| 开发 TL | 阻塞项、代码差异、GAP、模块下钻 | 评论反馈、外部依赖 |
| 客户经理 | 评论反馈、问题清单、外部依赖（均带一键复制） | 代码差异、GAP |
| 新人 | 技术架构、核心流程、模块下钻、文档中心 | 评论反馈、外部依赖 |

## 五、落地顺序（对应结构改动，不含具体实现）

1. **P0**：把内联在 HTML 里的 12 类数据抽成 `data/*.json`，index.html 改为 fetch 渲染
2. **P1**：加角色切换条 + 卡片按 `visibleTo` 过滤
3. **P2**：评论/问题/依赖三类卡片加"一键复制"按钮
4. **P3**：代码差异接 git diff 自动生成，评审 P0/P1/门禁接原文半自动解析
